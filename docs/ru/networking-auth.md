# Сеть и Аутентификация

> **Модуль:** `docs/ru/networking-auth.md`
> **Контекст:** Взаимодействие с API, управление сессиями и синхронизация данных сервера.

## 1. Конфигурация сетевого стека

Aura Launcher централизует все HTTP-взаимодействие через современный асинхронный сетевой стек, предоставляемый **Ktor Client** с движком **OkHttp**.

### 1.1 Инфраструктура (`networkModule`)

**Источник:** `hivens.launcher.di.Modules.kt`

Сетевой стек инициализируется как синглтон в графе Koin.

* **OkHttpClient:** Служит базовым движком. Настроен с поддержкой **SOCKS Proxy** (всегда включен через `AppConfig.Proxy`) и увеличенными таймаутами для работы с медленными соединениями.
* **Ktor HttpClient:** Основной интерфейс для выполнения запросов. Он оборачивает предварительно настроенный `OkHttpClient` и устанавливает стандартные плагины:
    * `ContentNegotiation`: Использует `kotlinx.serialization` для парсинга JSON.
    * `HttpTimeout`: Устанавливает глобальные лимиты запросов (10 мин на запрос, 30 сек на подключение).
    * `DefaultRequest`: Автоматически добавляет заголовок `User-Agent` (`SMARTYlauncher/X.X.X`) и `Content-Type`.

```kotlin
// Концептуальная конфигурация
single<HttpClient> {
    HttpClient(OkHttp) {
        engine { preconfigured = get<OkHttpClient>() }
        install(ContentNegotiation) { json(...) }
    }
}
```

## 2. Архитектура аутентификации

Система аутентификации выступает мостом к бэкенду SmartyCraft (API V3). Она использует кастомную реализацию вместо декларативного REST-интерфейса.

### 2.1 Контракт (`IAuthService`)

**Источник:** `hivens.core.api.interfaces.IAuthService`

Core модуль определяет контракт, используемый UI слоем.

```kotlin
interface IAuthService {
    @Throws(AuthException::class)
    suspend fun login(login: String, password: String, serverId: String): SessionData
}
```

### 2.2 Реализация (`AuthService`)

**Источник:** `hivens.core.api.AuthService`

Реализация использует `HttpClient` для отправки form-data запроса на `AppConfig.AUTH_URL`.

* **Логика безопасности:**
1. **MD5 Хеширование:** Пароль хешируется (MD5) перед отправкой.
2. **Hardware ID (MAC):** Генерируется случайный MAC-адрес, чтобы эмулировать новое устройство при каждом входе (`generateRandomMac`).
3. **Генерация Game Token:** Сервис реализует кастомное криптографическое рукопожатие, включающее AES-дешифровку ключа сессии и MD5 "соление" (`generateGameToken`).


* **Формат запроса:**
  Отправляет параметр формы `json`, содержащий сериализованный объект `AuthRequest` с системной телеметрией (ОС, версия Java, разрядность).
* **Обработка ответа:**
* Вручную парсит сырые строковые ответы для обработки устаревших текстовых ошибок ("Bad login", "User not found").
* Декодирует JSON в `AuthResponse`, если первичная проверка пройдена.



### 2.3 Данные сессии (`SessionData`)

**Источник:** `hivens.core.data.SessionData`

Успешный вход возвращает объект `SessionData`.

| Свойство       | Описание                                                                         |
|----------------|----------------------------------------------------------------------------------|
| `accessToken`  | Вычисленный "Финальный Игровой Токен", необходимый для входа на серверы.         |
| `uuid`         | UUID игрока (очищенный, без дефисов).                                            |
| `fileManifest` | Список файлов (`FileManifest`), возвращенный сервером для проверки целостности.  |
| `balance`      | Баланс пользователя (Реальная валюта/Монеты), возвращенный системой авторизации. |

## 3. Управление серверами

Получение статуса серверов и новостей обрабатывается сервисом `ServerListService` через репозиторий.

### 3.1 Паттерн Репозитория

**Источник:** `hivens.core.api.ServerRepository`

`ServerRepository` отвечает за получение и кеширование `DashboardData`.

* **Механизм:** Выполняет GET запрос к бэкенду.
* **Данные:** Возвращает `SmartyResponse`, содержащий список серверов и новости.

---

## 4. Загрузка файлов

Игровые ассеты и библиотеки загружаются с использованием `FileDownloadService`.

* **Движок:** Использует тот же экземпляр `OkHttpClient` (напрямую или через Ktor), используя общий пул потоков.
* **Целостность:** Загрузки проверяются на соответствие хешам, предоставленным в `FileManifest` (из ответа авторизации).
